# MSA-3-NovaMarket: Микросервисная Архитектура и Оркестрация

Репозиторий содержит решения для задач по проектированию, реализации, масштабированию и обеспечению надёжности микросервисной архитектуры на примере платформы NovaMarket.

## Структура проекта

- **`Task1/`**: Архитектурный анализ и проектирование саги оформления заказа.
- **`Task2/`**: Архитектурное решение для компонента "История заказов".
- **`Task3/`**: Динамическое масштабирование приложения в Kubernetes.
- **`Task4/`**: Повышение надёжности приложения (Rate Limiting, Circuit Breaker).

---

## Task 1: Архитектурный анализ и проектирование саги оформления заказа

Данный раздел содержит архитектурные материалы, описывающие **сагу оформления заказа** в системе NovaMarket Marketplace.

### Структура

- [`c2.puml`](./Task1/results/c2.puml) — PlantUML-диаграмма (C4-контейнер), показывающая общую архитектуру NovaMarket Marketplace.
- [`saga-events.md`](./Task1/results/saga-events.md) — Реестр событий, участвующих в саге оформления заказа.
- [`sequence-ok.puml`](./Task1/results/sequence-ok.puml) — PlantUML-диаграмма последовательности (Sequence Diagram), показывающая успешный сценарий оформления заказа.
- [`/sequence-fail.puml`](./Task1/results/sequence-fail.puml) — PlantUML-диаграмма последовательности, показывающая сценарии обработки ошибок при оформлении заказа.

### Описание

Решение описывает архитектурные аспекты, связанные с оформлением заказа и историей заказов в **NovaMarket Marketplace**. Оно включает в себя общую структуру системы, сагу бизнес-процесса оформления заказа, а также события, участвующие в этой саге, и её различные сценарии (успешное выполнение, ошибки).

Данный раздел содержит архитектурное решение для компонента **истории заказов** в системе NovaMarket Marketplace.

### Структура

## Task 3: Динамическое масштабирование приложения в Kubernetes

Эта директория содержит файлы, используемые для демонстрации и проверки концепции **динамического масштабирования** (Horizontal Pod Autoscaling - HPA) в Kubernetes.

### Структура

- [`deployment.yaml`](/Task3/results/deployment.yaml) — Манифест для деплоя тестового приложения (`scaletestapp`).
- [`service.yaml`](/Task3/results/service.yaml) — Манифест для сервиса, предоставляющего доступ к приложению и используемого Prometheus для обнаружения целей.
- [`servicemonitoring.yaml`](/Task3/results/servicemonitoring.yaml) — Манифест ServiceMonitor, настраивающий Prometheus на сбор метрик с Pod'ов приложения `task3`.
- [`adapter-values.yaml`](/Task3/results/adapter-values.yaml) — Файл значений для настройки Prometheus Adapter (определяет правило для метрики RPS).
- [`hpa.yaml`](/Task3/results/hpa.yaml) — Манифест HPA, масштабирующий приложение на основе **утилизации памяти**.
- [`hpa-rps.yaml`](/Task3/results/hpa-rps.yaml) — Манифест HPA, масштабирующий приложение на основе **внешней метрики RPS** (запросов в секунду на под).
- [`locustfile.py`](/Task3/results/locustfile.py) — Сценарий для инструмента нагрузочного тестирования Locust.
- [`screenshots/`](/Task3/results/screenshots) — Директория со скриншотами, подтверждающими работу HPA.

### Описание

В рамках задания была продемонстрирована работа HPA двумя способами:

1.  **На основе утилизации памяти**: Использовался `results/hpa.yaml`.
2.  **На основе внешней метрики (RPS)**: Использовался `results/hpa-rps.yaml` совместно с Prometheus и Prometheus Adapter (настроенный через `results/adapter-values.yaml`).

## Task 4: Повышение надёжности приложения

Эта директория содержит файлы конфигурации NGINX, используемые для демонстрации и реализации механизмов повышения надёжности приложения: **Rate Limiting** и **Circuit Breaker**.

### Структура

- [`nginx-rate-limiter.conf`](/Task4/results/nginx-rate-limiter.conf) — Конфигурационный файл NGINX для настройки ограничения частоты запросов (Rate Limiter) с разными лимитами для веб- и мобильного приложений.
- [`nginx-circuit-breaker.conf`](/Task4/results/nginx-circuit-breaker.conf) — Конфигурационный файл NGINX для настройки паттерна Circuit Breaker при взаимодействии с внешними сервисами (например, логистикой).

### Описание

В рамках задания были реализованы два аспекта надёжности: rate-limiter и circuit-breaker
